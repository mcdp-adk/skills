# Project Knowledge

## Purpose and model

Make the knowledge a project needs enter its development, creation, and completion, then let evidence and learning change it as the work changes. Project knowledge is the understanding people and Agents need and the project artifacts that express it, in any medium. No carrier has default priority.

Use this causal model to orient the work:

```text
project work creates a knowledge need
→ knowledge is found or produced
→ a suitable carrier and connection make it usable
→ development, creation, or decisions consume it
→ evidence and learning may change the knowledge
```

This is a model of causes and relationships, not a checklist. Select only the branch the current request needs: `establish`, `use`, or `evolve`.

## Choose a branch

### `establish`

Use this branch when project work needs a durable knowledge arrangement, discoverable entry point, missing connection, or repair to an existing one.

1. Start from the project work and its actual consumers: what must someone understand, decide, do, or evaluate? Inspect the existing entry points and the documents and artifacts that answer those needs.
2. Find existing knowledge and carriers before creating structure. Identify which sources are authoritative, current, directly verifiable, inferred, uncertain, or conflicting.
3. Establish the smallest sufficient carrier and connection. Reuse or repair an existing source and entry point where possible; add a new source only for a real durable gap. Link readers to the artifact that expresses behavior or evidence most accurately. If no durable need exists, create no structure.

**Complete when:** the actual consumers can find and use the knowledge needed for the stated project work, authority and uncertainty are visible, each meaning has one suitable authoritative expression, and no unnecessary structure was added.

### `use`

Use this branch when existing project knowledge must guide a concrete decision, action, or evaluation.

1. Name the decision, action, or evaluation and the result it must affect. Locate the relevant knowledge sources and action-bearing artifacts selectively, then inspect enough of each to support that result.
2. Determine what the sources establish about the current work: intent, constraints, evidence, learning, current behavior, and remaining uncertainty. When authority, certainty, or source conflict materially blocks the application, expose it and obtain the resolution the current task requires.
3. Apply the selected knowledge to the work. Use it to choose among options, shape the action, set evaluation criteria, or produce the result; keep the supporting source and action-bearing artifact connected. Use summaries for orientation, then inspect the source whose details control the action.

**Complete when:** the knowledge has observably influenced the current decision, action, evaluation, or resulting artifact; its supporting sources remain connected; and any material authority or certainty issue is resolved or explicitly carried as a limitation of the result.

### `evolve`

Use this branch when implementation, experiments, feedback, or learning may have changed durable project knowledge.

1. Compare the affected intent, design, decisions, and direction with what implementation or other evidence now shows. Identify what changed while preserving the distinction between observed behavior, evidence, interpretation, and confirmed change.
2. Decide whether the change is durable. Keep immediate progress and other execution-only detail in the current working context; preserve a discovery in project knowledge when future people or Agents will need it.
3. If durable knowledge changed, update the smallest affected authoritative source and its connections. Otherwise, leave project knowledge unchanged.

**Complete when:** every affected durable source is updated or consciously left unchanged because no lasting knowledge changed, evidence and uncertainty are represented at the right level, and readers can still follow the valid connections to implementation and other carriers.

## Principles

- **Project work first.** Let the work create the knowledge need; do not make knowledge maintenance an automatic lifecycle around every task.
- **Carrier-neutral.** People, Agents, and project artifacts in any medium can carry knowledge; choose the source that most accurately serves the current consumer.
- **Selective loading.** Follow the smallest relevant path from an entry point and load more only when the current decision or action needs it.
- **Minimal sufficiency.** Prefer the least structure that gives the consumer a reliable path; let real independent responsibilities earn new carriers.
- **Source, authority, and certainty visibility.** Keep the basis and status of important knowledge visible.

People and Agents may research, design, implement, evaluate, and learn. For a concrete question, assign or confirm participation according to knowledge, capability, authorization, risk, verifiability, and willingness; treat an Agent's inference or preference as unconfirmed until the appropriate authority confirms it.
