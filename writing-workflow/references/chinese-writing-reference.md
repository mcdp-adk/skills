# 中文写作参考

## 空格

中文与英文、中文与阿拉伯数字之间通常留一个空格：

```text
使用 Git 管理 3 个仓库。
```

数字与单位通常留一个空格：

```text
文件大小为 5 MB，超时时间为 200 ms。
```

百分号、角度等惯用形式不加空格：

```text
CPU 使用率为 95%，温度为 32°C。
```

全角标点前后不额外留空格。代码、路径与命令内部遵循自身语法。

## 标点与括号

中文句子使用全角标点；完整英文句子和代码使用半角标点：

```text
注意：该接口需要鉴权，请先获取 Token。
Run `npm install`, then run `npm test`.
```

中文语境通常使用全角括号。括号内主要是英文、版本号或代码时，可以使用半角括号：

```text
请运行安装命令（详见下方说明）。
该项目基于 Spring Boot (v3.2.0) 开发。
```

引号遵循项目约定，并在全文保持一致。代码字面量使用反引号。

## 术语

以下内容通常保留原文：

- 专有名词，如 React、Kubernetes、Redis；
- 行业缩写，如 API、SDK、CLI、CI/CD；
- 协议与格式，如 HTTP、TCP/IP、JSON；
- 命令与代码，如 `npm install`、`git commit`；
- 没有稳定或更清楚中文译法的术语，如 debounce、middleware。

有公认中文表达时使用中文，例如数据库、浏览器、版本控制、负载均衡。具体词语仍取决于项目语境与目标读者，不使用固定词表替代判断。

只有读者可能不熟悉且对照确实有助于理解时，才在首次出现处补充中英文说明：

```text
本系统使用死信队列（Dead Letter Queue）保存处理失败的消息。
```

后续使用已经确定的称呼，不重复添加对照。

## 自然表达

将英语被动结构改为自然动作：

```text
生硬：这个函数被用来计算用户的折扣。
自然：这个函数用于计算用户折扣。
```

删除无实际作用的代词和套话：

```text
冗长：如果你想要获取更多信息，请参考下面的文档。
直接：更多信息请参考下方文档。
```

拆开长定语和多层从句：

```text
生硬：这是一个可以帮助开发者在不需要手动配置复杂构建工具链的情况下快速搭建现代化前端项目的脚手架工具。
自然：这是一个前端脚手架工具，帮助开发者快速搭建项目，免去手动配置构建工具链的麻烦。
```

将抽象表达改为具体对象、动作与结果：

```text
空泛：后续需要完成能力链路的闭环建设。
具体：下一步补齐失败重试，并记录每次重试结果。
```

## 检查要点

- 语序是否自然，是否存在机翻句式、过长定语或无具体含义的抽象词？
- 空格、标点、括号和数字单位是否保持一致？
- 技术字面量是否准确，术语是否避免过度翻译和重复对照？
- 相同概念是否使用统一称呼？
