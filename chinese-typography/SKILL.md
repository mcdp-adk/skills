# 中文排版

让中文回复和文档使用一致的排版。日常生成时直接遵循这些约定，无需向用户解释排版过程；专门整理已有文本时，只调整排版，保留措辞、原意和结构。

## 正文约定

用户或项目的明确要求优先。没有明确要求时，采用以下默认值；已有文本的简繁体、地区习惯和一致的引号样式继续沿用。

| 情况 | 写法 |
| --- | --- |
| 中文与拉丁字母、阿拉伯数字相邻 | 留一个半角空格，如 `用 Python 处理 8 份记录`。专名内部按正式写法保留。 |
| 数值与单位符号 | 通常留空格，如 `512 MB`、`35 °C`；角度写 `45°`，日常文案百分比写 `8%`。专业文档遵循其计量规范。 |
| 中文句子的标点 | 使用 `，。；：？！` 和全角括号，并列词语按语义使用顿号，如 `缓存（cache）已更新。`。标点两侧不额外加空格；完整英文片段内部沿用英文标点。 |
| 字母和数字的字符形式 | 使用半角字母、阿拉伯数字；保留专名大小写、数值和编号内部形式，以及“一次”“第二节”等原有汉字数字。 |
| 引号与书名号 | 新写简体中文用 `“”`，内层用 `‘’`；书名用 `《》`。 |
| 省略号与破折号 | 中文正文写作 `……`、`——`；按含义区分破折号、区间连接符和负号。 |

这些约定以[《中文文案排版指北》](https://github.com/sparanoid/chinese-copywriting-guidelines/blob/master/README.zh-Hans.md)为主要参考，用于统一日常输出。风格有合理选择时，以当前文本的一致性为准。

## 排版边界

按文字的用途判断能否修改，不能只看字符。逐字引用、日志、字符示例和错误示例保持原样；代码、命令、路径、URL、标识符及配置值也保持字面内容，即使它们没有用反引号包围。

在 Markdown 中，调整读者看到的正文，保留标记、链接目标、转义及承担结构作用的空白。例如 `支持**JSON**导出` 可写成 `支持 **JSON** 导出`，空格放在强调标记外；纯中文链接无需另加空格。

需要编辑链接或标题、处理表格中的特殊字符，或生成、修改 Mermaid 等嵌入内容中的中文时，查阅 [语法中的中文排版](references/markdown-syntax.md) 对应部分。原样保留的代码块无需展开检查。

## 完成判断

排版应前后一致，原意及受保护内容保持不变。修改已有文件时，检查差异是否仅包含预期调整；如果改到了语法定界符、转义或结构，用项目已有的解析或渲染方式验证。
