# 翻译与审校方法

按当前疑点查阅：日语关系看“理解原文”，按钮和标题看“短文本”，插值与片段看“动态组合”，修改译文后看“双语审校”。下列短例为说明方法而自拟，中文均需结合实际语境选择。

## 理解原文

先弄清谁对谁做什么，以及对象、条件、数量、视点和确定程度。上下文不足时，回查相邻对白、说话人、动作对象或触发条件；仍不能确定的，保留疑义和出处。中文可以重排句法，但不能凭空补动机、性别或结果。

| 难点 | 怎么判断 | 示例与易错处 |
| --- | --- | --- |
| 省略 | 沿话题、应答和叙述视点找行动者与对象；中文能自然省略时，不必把查明的信息全写出 | 「もう食べた？」在询问对方时可译“已经吃过了吗？”。孤立句不能证明主语是谁 |
| 授受 | 分清动作方向、受益者及说话人的立场，再处理感谢、请求或施惠口吻 | 「手伝ってくれてありがとう」是感谢对方帮忙；`てもらう` 从接受帮助的一方叙述，不能只替换动词后缀 |
| 受身与使役 | 核对施事者、受影响者，以及强迫、许可或困扰是否有上下文依据 | 「行かせた」可能是让去，也可能是准许去；使役本身不等于强迫。使役受身常有被迫意味，仍须核对实际主体 |
| 否定与条件 | 找出否定管到哪个谓词、数量或引语，检查条件是否仍成立 | 「嫌いなわけじゃない」不能简化成“喜欢”；「三つしかない」需同时保留“三个”和“只有” |
| 时态与体 | 结合动词性质和时间关系，区分过程、结果状态、反复和经历 | `ている` 不总是“正在”；「窓が開いている」可说明窗户开着的结果状态。不能为中文顺口把尚未完成写成已经完成 |
| 情态与信息来源 | 分清意图、推测、传闻与确定陈述，保留证据强度 | 「来るかもしれない」是“可能会来”。「来るそうだ」的传闻与「来そうだ」的迹象判断不同 |
| 视点与指示 | 查心理主体、叙述焦点及双方共享的信息，避免提前揭示身份 | 「見られている気がする」保留“感觉有人在看”的不确定性；`あの人` 不因译者知道身份就必须改成人名 |
| 敬语与称谓 | 看谁抬高谁、谁谦抑自己，以及公私场合与关系变化 | `いらっしゃる` 的动作义需另判，敬意可由称谓和句式表达；不能机械加“您”或“您好” |
| 方言与口癖 | 判断其身份、亲疏、地域或喜剧作用，用中文中合适的差异补偿 | 不自动把某种方言换成中国地域方言；必要的口癖重复可保留，不为避免重复而轮换同义词 |
| 拟声拟态 | 先分声音、动作、状态或感受，再看修饰对象、持续时间与节奏 | 「ちらちら」描述目光与光亮时需要不同表达；中文可用动词、状语或拟声词，不强求同词对应 |
| 双关与文字游戏 | 同时查看字面义、笑点机制、角色意图及后文是否回收 | 尝试保留双层效果；无法兼顾时记录损失和取舍，避免加注直接揭穿后文谜底 |

这些检查是翻译判断方法。语法资料帮助识别可能关系，作品原文决定当前关系；某个词形、敬语或语气词不能单独证明角色性别和性格。

时态体可对照东京外国语大学的[结果状态说明](https://www.coelang.tufs.ac.jp/mt/ja/gmod/contents/explanation/046.html)，情态可查其[推测与传闻教材](https://www.coelang.tufs.ac.jp/mt/ja/gmod/courses/c01/lesson19/step2/explanation/076.html)。[国际交流基金的「そうです」教材](https://www.kyozai.jpf.go.jp/kyozai/material/BTS00094/ja/render.do)直接对比了样态与传闻的接续形式；这些语法区别支持保留信息来源和确定程度，不强制某一种中文句式。

查证语法可用 [NINJAL 授受研究](https://repository.ninjal.ac.jp/record/3355/files/JC-G-08-02.pdf)、[单句与复句研究](https://repository.ninjal.ac.jp/record/2717/files/crpr_12-06.pdf)和[文化庁《敬語の指針》](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/kokugo/kokugo_33/pdf/siryou_2.pdf)。这些资料分别支持授受视点、省略或句法关系、敬语功能的查证，不为表中每个中文候选背书。[NINJAL 查证指引](https://www.ninjal.ac.jp/utility/contact/how-to-search/)可用于继续寻找辞书和语料；[拟声拟态介绍](https://kotoba.ninjal.ac.jp/digest/02/d-02-06/)说明声音与状态表达的区别。

## 短文本

先把短文本放回所属界面或剧情，连看相邻标签、同组选项及前后文。必要时追查触发行为来理解用途，但译文只传达原文表达的信息。

| 用途 | 重点核对 | 中文选择示例 |
| --- | --- | --- |
| 操作按钮 | 动作、对象、作用范围，以及返回和取消是否不同 | `戻る` 常可译“返回”；只有确实表达取消时才用“取消” |
| 剧情选项 | 说话人的态度、犹豫和承诺程度，同组选项的差别 | 「考えておく」可以是“我会考虑的”，不能为省字写成“答应” |
| 标题与称号 | 命名意图、作品风格、双关及是否提前暴露信息 | 夸张称号可保留夸张，普通标签不必一律写成四字成语 |
| 状态与提示 | 数值、条件和结果之间的关系 | `あと3回` 通常强调“还差／还剩 3 次”，不是“已完成 3 次”；具体动词由上下文决定 |

候选写出后，检查中文是否有生硬搭配或日式语序，同组用语是否清楚区分。对照原文确认没有因精简而删掉限制、否定或对象。字数合适、术语匹配或没有语法错误，都不足以单独判定短文本通过。常见菜单词和称谓另见[术语辨义](terminology.md)。

## 动态组合

找到片段的使用位置和组合条件，再判断它在完整中文里充当什么成分。复用片段在不同位置语法功能不同时，可采用上下文变体或必要的组合适配。

例如，`高身長` 独立作属性标签时可用“高个子”；与 `の`、`先輩` 组合时，完整表达可为“高个子的前辈”。回填方案要同时照顾独立标签和组合结果，不能给片段套一个中文后就停止检查。

下面用抽象命名占位符说明重排，格式本身不属于某个指定引擎：

```text
原文：{from}が{to}に{item}を渡す
中文：{from} 把 {item} 交给 {to}
```

`{to}` 与 `{item}` 的出现顺序改变了，身份和作用仍须对应。只有格式支持时才重排；固定位置的参数要保持其约定，或作有依据的最小适配。变量名、参数类型、转义与控制关系分别检查。

玩家输入也可能进入组合。姓名后的称谓应结合关系处理，不能把输入变量替换成猜测的名字。选择代表性姓名、边界长度和相关符号验证；空值等情况只有游戏允许或处理它们时才纳入。数值、条件或性别等会改变措辞的分支，应核对各类完整表达，再按风险安排运行观察，无需穷举所有输入。

文本标签的作用范围也属于含义的一部分。移动带样式的文字时，要确认强调、颜色或链接仍作用于同一内容。实际语法以目标格式为准：例如 [Ren'Py Text](https://www.renpy.org/doc/html/text.html) 使用方括号插值、花括号文本标签，并在插值后处理样式和排版；[Godot 国际化文档](https://docs.godotengine.org/en/4.5/tutorials/i18n/internationalizing_games.html)另有上下文与命名占位符机制。不能混用示例语法。

## 双语审校

逐个意义单元对照原文、译文和上下文，找遗漏、增译、对象错配、否定或条件丢失及语域变化。查看术语约定是否适用于这一处，不能只看词形命中。中文连读时检查照应、人物口吻和短文本用途；润色后再对照原文。

修改理由应能指出实际差异。例如把“还有三个”改回“只有三个”，理由是恢复限制意义；只觉得另一个同义词更好听，通常不足以改动已合适的译文。后文揭示新义时，回查前文及共用的组合片段。

来源定位、疑义和修改理由保留到足以继续复核即可，沿用项目已有记录，不要求逐条填写固定表。发现错译要进入译文基准；其回填与呈现检查见[验证与交付](verification.md)。

[ATA 的译文审查方法](https://www.atanet.org/translation/how-to-review-a-translation/)支持逐意义单元核对及修改后回看原文；[译文编辑协作建议](https://www.atanet.org/translation/editing-translations-tips-for-cultivating-a-collaborative-mindset/)提醒区分纠错和个人偏好。[IGDA 的上下文实践](https://igda.org/news-archive/high-quality-localization-help-loc-help-you/)强调游戏功能与剧情信息的重要性。这些是方法依据，不要求个人补丁项目照搬商业团队的人员配置。
