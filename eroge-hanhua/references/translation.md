# 翻译与审校

本参考用于日文 R18 游戏的文本汉化。按任务查阅[理解原文](#理解原文)、[短文本](#短文本)、[动态组合](#动态组合)和[双语审校](#双语审校)。示例为方法说明而自拟，中文候选需放回具体语境判断。

## 理解原文

先确定行动者、对象、人物关系和叙述视点，再看条件、数量、时间与确定程度。日语省略的信息可从相邻对白、说话人、动作对象或触发条件追查。理解时补足关系，成文时只表达原文需要传达的信息；中文可以自然省略主语，也可以重排句法。

| 判断对象 | 查证方法与示例 |
| --- | --- |
| 省略与指代 | 沿话题和应答找主体。「もう食べた？」在询问对方时可译“已经吃过了吗？”，孤立句并未说明主语。`あの人` 保留当前视点知道的身份信息 |
| 授受 | 找动作方向、受益者和叙述立场。「手伝ってくれてありがとう」感谢对方帮忙；`てもらう` 从接受帮助的一方叙述。先理清关系，再表达请求、感谢或施惠口吻 |
| 受身、使役与使役受身 | 分清施事和受影响者。「行かせた」可以表达让去或准许去；强迫、许可及困扰须结合上下文判断。使役受身常带被迫意味，仍要核对主体 |
| 否定与条件 | 确定否定作用于哪个谓词、数量或引语。「嫌いなわけじゃない」只否定“讨厌”这一判断；「三つしかない」同时表达“三个”和“只有”。条件的适用范围也要保留 |
| 时态与体 | 结合动词性质辨认过程、结果状态、反复或经历。「窓が開いている」可指窗户开着，`ている` 不固定对应“正在”。按时间关系区分尚未完成和已经完成 |
| 情态与信息来源 | 分清意图、推测、传闻和确定陈述。「来るかもしれない」保留“可能”；「来るそうだ」为传闻，「来そうだ」为迹象判断。译文保留各自的确定程度 |
| 心理视点 | 确认谁在感知或推测。「見られている気がする」表达“感觉有人在看”，不能删去感知限定后写成确定事实 |
| 敬语与称谓 | 查抬高或谦抑的是谁、处于什么关系与场合。`いらっしゃる` 的具体动作义另判，敬意可通过称谓和句式表达 |
| 方言与口癖 | 判断它承担身份、亲疏、地域还是喜剧作用，再选择中文表达方式。人物固定口癖可以重复；将日语方言改成中国地域方言需要有适合作品的理由 |
| 拟声拟态 | 区分声音、动作、状态和感受，再看修饰对象及节奏。「ちらちら」形容目光和光亮时需要不同表达，可采用中文动词、状语或拟声词 |
| 双关与文字游戏 | 核对字面义、笑点、人物意图及后文回收。不能兼顾时记录实际损失和取舍，保留原文安排的揭示时机 |

自称、敬语或单个语气词可提供口吻线索，人物性别、年龄和性格仍由作品证据判断。成人语境同样需要完整语法分析；例如动作名称与“让某人作出动作”的方向不同，详见[动作与状态](terminology.md#动作与状态)。

语法查证可用 [NINJAL 授受研究](https://repository.ninjal.ac.jp/record/3355/files/JC-G-08-02.pdf)、[单句与复句研究](https://repository.ninjal.ac.jp/record/2717/files/crpr_12-06.pdf)及[文化庁《敬語の指針》](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/kokugo/kokugo_33/pdf/siryou_2.pdf)，分别查看授受视点、句法关系和敬语功能。声音与状态的区别见 [NINJAL 拟声拟态介绍](https://kotoba.ninjal.ac.jp/digest/02/d-02-06/)。

东京外国语大学的[结果状态说明](https://www.coelang.tufs.ac.jp/mt/ja/gmod/contents/explanation/046.html)、[推测与传闻教材](https://www.coelang.tufs.ac.jp/mt/ja/gmod/courses/c01/lesson19/step2/explanation/076.html)，以及[国际交流基金「そうです」教材](https://www.kyozai.jpf.go.jp/kyozai/material/BTS00094/ja/render.do)可用于核对时态体和接续形式。这些资料解释日语关系，表中中文是结合语境选择的示例。

## 短文本

将选项、按钮、标题、称号放回所属界面或剧情，连看前后文和同组文字。必要时追查触发行为，理解标签的用途；译文保留原文的信息量，隐藏结果和后续剧情仍按作品安排呈现。

| 用途 | 审校重点 |
| --- | --- |
| 操作按钮 | 动作、对象和作用范围要清楚。`戻る` 常可用“返回”；是否表达取消，要查实际用途。短按钮使用自然的动作表达 |
| 剧情选项 | 保留态度、犹豫和承诺程度。「考えておく」可译“我会考虑的”，改成“答应”会增强承诺。同组选项应读得出原有差别 |
| 标题与称号 | 保留命名意图、双关和作品风格。夸张称号可以夸张，普通标签按普通中文写；独立属性和组合称号分别判断词形 |
| 状态与提示 | 对准数值、条件和结果。`あと3回` 表达“还差／还剩 3 次”，具体动词从用途确定 |

写出候选后先读中文，检查搭配、语序和同组表达是否自然；再回看原文，核对限制、否定、对象和语气是否齐全。长度、语法及术语匹配只能检查其中一部分，短文本是否通过还取决于它在当前用途下是否准确、好懂。

## 动态组合

动态组合包括运行时插值、多个片段拼接，以及按状态选用不同措辞。翻译时追查片段的各个使用位置，按完整表达确定中文语法。片段承担不同语法功能时，可采用上下文变体或必要的组合适配。

例如，`高身長` 独立作属性可用“高个子”；与 `の`、`先輩` 组合时，完整表达可为“高个子的前辈”。要同时照顾属性标签和组合称号，才能决定回填哪种词形。

下例用抽象命名占位符说明中文重排，不代表具体引擎语法：

```text
原文：{from}が{to}に{item}を渡す
中文：{from} 把 {item} 交给 {to}
```

顺序改变后，占位符的身份和作用保持对应。先确认格式是否支持重排；固定位置参数按其约定处理，需要适配时说明依据。连同变量名、类型、转义和控制关系一起检查。样式标签随文字移动时，强调、颜色或链接应继续作用于原来的内容。

输入姓名与后接称谓也属于完整表达。保留玩家输入变量，依据人物关系选择称谓。核对会改变措辞的数值、条件或性别分支；运行时选代表性姓名、长度边界和有关符号，空值仅在游戏允许或处理时纳入。文本逻辑的各类表达要查清，玩家可能输入的所有字符串无需穷举。

具体语法查目标引擎文档。[Ren'Py Text](https://www.renpy.org/doc/html/text.html)使用方括号插值、花括号文本标签；[Godot 国际化文档](https://docs.godotengine.org/en/4.5/tutorials/i18n/internationalizing_games.html)介绍其上下文和占位符处理。使用这些例子时保留引擎边界。

## 双语审校

逐个翻译单元核对原文、译文和上下文，重点查漏译、增译、对象错配、否定与条件丢失、语域及信息强度变化。词表约定须适用于当前用法；指代已经查清时，译文仍按原文选择明确名称或委婉表达。

对照审校后按剧情或功能连读中文，检查照应、人物口吻、搭配和选项差别。改动应能说明实际问题：将“还有三个”改为“只有三个”恢复了限制意义；单纯偏好另一个同义词，不足以推翻已经合适的表达。每次润色后重新核对原文。

审校者先独立判断含义，再评估初译及修改理由。后文提供新线索时，回查相关前文和共用片段；有疑义的位置保留来源与待查问题。沿用项目记录，记录到足以复核即可，修正后的完整文本进入译文基准。

[ATA 译文审查方法](https://www.atanet.org/translation/how-to-review-a-translation/)说明按意义单元对照及改后复核；[编辑协作建议](https://www.atanet.org/translation/editing-translations-tips-for-cultivating-a-collaborative-mindset/)区分纠错与个人偏好。[IGDA 上下文实践](https://igda.org/news-archive/high-quality-localization-help-loc-help-you/)提供游戏功能和剧情信息帮助翻译的实例。这些方法可用于个人补丁项目，具体人员分工按工作量安排。
