# 日文 R18 游戏汉化

作为汉化工作的入口，帮助 agent 从用户提供的游戏和目标出发，自主安排调查、制作与验证，交付能读、能用、可继续维护的中文补丁。项目约定、工具和译文尚未建立时，由 agent 在授权范围内逐步准备。

默认按公开发布的质量要求制作适用于指定游戏版本的文本汉化补丁，包含普通剧情、成人内容、界面、动态文字及载入和显示译文所需的适配；图片重绘和配音默认不纳入。用户明确的范围与质量要求优先，记录调整的影响。交付补丁与公开发布分别按用户授权处理。

## 开始与恢复

先读取已有约束、当前进度和与本次工作相关的复盘，确认可访问的材料及已有成果。新项目从调查开始；继续制作时从尚缺的结果接续；单独审校或局部修订只进入所需环节，复查受影响的译文和资源。

没有目录约定时，在已授权工作区自行安排工作材料、独立测试和交付物的位置，说明用途并留下入口。原始游戏及资源只读保留；用户游玩的游戏、存档、设置等按具体授权访问。目录安排不能扩大访问权限，制作补丁也不授权安装到游玩环境或改写用户存档。

事实调查、常规工具选择、工作划分和检查安排由 agent 负责。只有确实缺少用户才能提供的资源或授权，或需要改变内容范围、质量、费用及最终使用方式时，才带着调查依据、推荐方案和影响请用户决定；已有明确指令直接沿用。

## 1. 调查路径与准备资源

核实原始游戏的位置与版本，调查主要文本来源、使用关系、提取和回填方式。**语言内容**传达剧情、人物表达或操作信息；**运行数据**承担执行控制、资源定位或状态标识。两者共用字符串时，改动前查清依赖，只作必要适配。文件类型和日文扫描用于查找线索，不能单独界定汉化范围。

沿主要显示路径调查字体及中文支持，留意实际存在的姓名等玩家输入功能。按拟采用的路径核实所需工具与操作能力，优先利用可用工具和已验证方法。适配字体时查[字体与布局](references/verification.md#字体与布局)；任何阶段启动游戏前，都先按[隔离与运行状态](references/verification.md#隔离与运行状态)确认独立的存档、设置、日志和缓存位置。

**完成条件**：形成有依据的处理方案，选出代表样本，列明资源缺口。向用户说明预期覆盖、保留的图片文字等内容、应用方式与已知限制；需要补充资源时说明用途和具体要求。资源齐备就继续；尚缺资源时继续不依赖它的调查和准备，未实际验证的路径标为待验证。

## 2. 用代表样本跑通流程

选择能检验主要提取、回填和显示路径的少量内容，沿计划用于全量制作的路径完成提取、翻译、回填、必要适配及应用。在独立测试副本中确认中文实际可读，相关操作可用。选择检查时查[补丁验证](references/verification.md#选择检查)，样本翻译也遵循下一节的语言要求。

**完成条件**：样本在真实游戏中显示和操作正确，能从维护材料重建结果，并按[样本方法的适用范围](references/verification.md#样本方法的适用范围)检查同类文本变化，证明方法可供后续制作使用。将未覆盖的来源、全量字符集和其他后续事项交给制作阶段；这里证明完整处理链路，工作量以代表样本为限。若样本失败，修复实际缺口后再沿该路径扩大制作。

工具服务于当前结果及已明确的后续制作，优先选择简单、可复用的做法，按实际缺口扩展。决定继续修工具或重验前，先判断缺失的是哪项必要能力、哪些已有结论受到影响。工具暂时不可用只暂停依赖它的操作；已有证据是否仍适用，按[确认交付对象](references/verification.md#确认交付对象)判断。必要检查仍须完成，失败尝试与未验证项如实记录。

## 3. 分批制作与审校

沿已验证路径盘点全部纳入内容，包括脚本、界面、资源元数据和动态表达式中的文字，保留来源与处理状态。新发现的独立处理路径先补对应样本验证。按连贯剧情或功能划分带上下文的翻译单元，单元可以跨行或跨字符串。

由 agent 阅读原文与上下文翻译，贴合原意，保留人物关系、视点、语气、语域、信息强度和不确定程度，使中文准确、通顺、一致。复用译文逐处核对语境，动态片段按完整表达判断；选项、按钮、标题和称号重点审校。

大量文本按上下文容量安排批次，主 agent 自行选择直接处理或委派翻译、审校，负责整体进度、疑义决策和合并后的统一。安排批次或续接时读取[批次与上下文](references/translation.md#批次与上下文)；理解原文、处理短文本、动态组合和双语审校时读取该参考的对应部分。判断称谓、多义词及语域时查[术语辨义](references/terminology.md)，通用候选以作品语境核定。

全部纳入内容均须对照原文和上下文审校，再按剧情或功能连读中文。审校随批次推进，修正写回译文基准；按制作中的实际改动及时检查回填、格式和显示。发现来源映射、格式或必要引用错误时，停止依赖该结果的回填、打包或运行，修正后再继续；不受影响的工作仍可推进。主 agent 的抽查与子 agent 的完成声明均不替代全量审校。有依据的译法由主 agent 确认；查证后仍影响人物设定、全篇风格或大量译文的重要取舍，附依据和候选交用户决定。

**完成条件**：纳入内容已完整翻译、审校并完成必要适配，从译文基准生成完整候选补丁。覆盖状态、疑义和检查结果可追溯，最终验收需检查的流程与风险已明确。

## 4. 验收实际补丁并交付

将实际候选补丁按拟交付说明应用到独立测试副本，核对译文、字体及必要配置与制作来源一致。核对全量语言审校的完成情况，完成适用的程序检查，并通过 Computer Use 或其他可用手段观察真实显示和相关流程。运行取样按改动与风险选择，与语言审校的覆盖范围分别说明。

需要进入特定场景时，按[到达测试场景](references/verification.md#到达测试场景)选择现成入口或构造独立测试状态，再由游戏实际载入验证。处理旧档反馈或迁移时，按[隔离与运行状态](references/verification.md#隔离与运行状态)使用获授权的数据副本，检查进度与其他状态的保持；首版以新游戏测试不排除后续旧档修复。

区分原版缺陷、汉化错误与运行状态影响，将修正写回维护来源，按影响范围复查。交付前查[确认交付对象](references/verification.md#确认交付对象)，确认已有证据适用于实际包。无法满足约定要求时，说明缺口与可行取舍，请用户决定受影响的范围或交付安排。

**完成条件**：交付适用于指定版本的补丁和使用说明，列明应用方式、实际检查结果、兼容限制及剩余问题，保留可继续维护的材料。结论限定于实际内容和验证范围。

## 持续维护的依据

材料随工作建立和更新，沿用项目已有位置；没有记录方式时使用简单文件即可。当前进度集中维护已完成事项、待办、阻塞及证据入口，交接引用实际材料；规格、工单等按项目需要采用。

| 材料 | 用途与更新时机 |
| --- | --- |
| 原文基准 | 指定版本的原文、资源及使用关系，用于判义和追溯 |
| 译文基准 | 当前完整译文及处理状态，是交付资源和派生显示数据的唯一译文维护来源；修正后重新生成受影响产物 |
| 项目术语表 | 人物名、专名及需统一的称谓，保留出处，区分候选与定译；每批读取相关条目，新发现或改译及时更新并回查受影响译文 |
| 复盘记录 | 调查、修复和验证得到的新结论、原因及证据、处理结果与未解决项；同类工作前查阅，记录区分实际结果与后续计划 |

术语登记与定译规则见[作品术语表](references/terminology.md#作品术语表)，批次衔接见[批次与上下文](references/translation.md#批次与上下文)。复盘仅追加有新信息的经验，工程细节保留在对应记录中，供后续遇到同类问题时使用。
