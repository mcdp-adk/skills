# 日文 R18 游戏汉化

将约定范围内的日文文本译成简体中文，交付适用于指定游戏版本的汉化补丁。范围包含普通剧情、成人内容、界面及动态生成的文字，以及使译文正常载入和显示所需的适配；默认保留图片和配音。以公开发布所需的完整质量要求工作，用户明确降低某项要求时，说明并记录影响。局部修订沿用已有项目约定，只处理本次指定内容及受影响部分。

## 1. 确定调查入口

读取项目约束和已有约定，核实游戏原始输入的位置、版本及允许访问的范围。缺少这些信息、无法安全开始调查时，先向用户询问。原始输入保持只读；用户的游玩环境按授权访问，制作补丁本身不授权安装补丁或修改用户存档。

调查需要解包、生成文件或建立测试副本时，先沿用已授权的工作位置；位置尚未明确，就提出具体目录与用途，请用户确认后再进行相关写入。等待期间可继续已授权的只读调查，完整交付安排在调查后确定。

核实当前会话能否处理目标文件、执行所需工具、调用子 agent 和操作游戏界面。支持按需发现工具时先查找。确实缺少必要能力，向用户说明受影响的工作、补齐方式和仍可继续的部分。检查尚未实现、工具故障及补丁错误分别由 agent 补做、修复和定位，不能归为能力缺失或据此降低验收要求。

## 2. 调查后向用户讲解

在允许范围内查清文本来源、使用关系、回填方式及主要限制。**语言内容**是向玩家传达剧情、人物表达或操作信息的文字；**运行数据**用于执行控制、资源定位或状态标识。两者可能共用一个字符串，修改前要追查依赖。脚本、代码、界面、资源元数据和动态表达式都可能含待译内容，文件类型与日文扫描仅作查找线索。

调查字体的实际显示用途、中文支持及可用来源，包含玩家输入中文的需求。运行游戏前，读取[补丁验证](references/verification.md)中的“隔离与运行状态”一节，查明存档、设置、日志和缓存的写入位置；确认隔离有效后才启动。

用用户能理解的方式解释发现：哪些内容可以汉化，哪些图片文字等内容会保留，为什么需要字体或其他资源，补丁怎样应用，以及已知限制会怎样影响游玩。给出推荐方案和有实际取舍的备选方案。此时的调查应足以支持这些决定；能从文件查明的事实、工具选择和检查方法由 agent 负责。

## 3. 确认位置与交付约定

依据调查提出具体安排，向用户列明各类文件的实际位置与用途：

| 对象 | 用途与边界 |
| --- | --- |
| 原始输入 | 用户提供的指定版本游戏及原始资源，作为只读依据 |
| 游玩环境 | 用户实际游玩的目录及存档、设置等用户数据；与测试用途分开 |
| 工作材料 | 提取文件、译文、术语表、加工文件、工具及处理记录 |
| 独立测试副本 | 从原始输入建立，应用候选补丁，并使用独立的运行数据位置 |
| 交付物 | 最终补丁及使用说明，存放在约定的交付位置 |

同时说明纳入和排除的文本、必要字体的来源与用途、交付文件及应用方式、验证安排和已知兼容限制。请用户决定尚未明确且影响文件存放、范围、资源准备、使用方式或质量承诺的部分；已有明确指令直接沿用，无需重复确认。

将约定保存在项目现有记录中。只有待决事项所影响的工作需要等待；其他已授权工作继续。后续发现改变约定时，先解释影响和推荐处理，再请用户决定新的取舍。

## 4. 建立翻译依据

盘点全部纳入范围的语言内容，使每项都能定位来源和处理结果。按含义与使用关系划分**翻译单元**：它可以跨行或跨字符串，但须带有足够的对白前后文、人物关系、显示位置或组合条件。陌生格式先用少量代表内容验证提取、回填和读取可行，再扩大处理规模；运行数据仅作确有需要的最小适配。

| 依据 | 职责 |
| --- | --- |
| 原文基准 | 指定版本的原文及资源、使用关系，用于判断原意 |
| 译文基准 | 当前确认的完整译文，是交付资源和需同步的派生显示数据的唯一译文维护来源 |
| 项目术语表 | 作品内人物名、专名及其他需统一表达的约定，区分候选与定译，保留必要出处 |

全量登记人物名和专有名词，包含配角、别名、昵称、职业及有指代作用的匿名人物称谓。其他词按辨义和统一表达的需要纳入。翻译与审校共同使用项目术语表；约定变化后同步译文并回查受影响位置。已有中文或词表与原文矛盾时，回到原文查证并修订约定。

## 5. 翻译并审校全部纳入内容

由 agent 直接阅读原文及上下文翻译。以贴合原意为先，保留人物关系、视点、语气、语域、信息强度与不确定程度，再使中文准确、通顺、一致。复用译文逐处核对语境，动态片段按完整表达判断。

- 判断省略、授受、使役、否定、敬语等关系，翻译短文本或动态组合，以及审校译文时，读取[翻译与审校](references/translation.md)对应部分。选项、按钮、标题和称号是重点审校对象。
- 辨别称谓、多义词、成人题材词汇或选择语域时，查[术语辨义](references/terminology.md)。它提供跨作品的词义和中文候选，作品定译仍依据原文与上下文；查明对象后保留原文的明确或委婉程度。

优先将批量翻译和审校交给子 agent，按连贯剧情或功能分工，提供必要上下文和当前术语信息，分开写入范围。主 agent 调度、合并、处理冲突、同步约定并抽查交界处。全部纳入内容均须对照原文审校，再按剧情或功能连读中文；主 agent 抽查不替代全量审校。

主 agent 确认有充分依据的译法。查证仍不能解决、且影响人物设定、全篇风格或大量译文的重要取舍，附依据与候选交用户决定。修订进入译文基准，未解决的疑义保留定位，继续查证。

## 6. 验证补丁并交付

设计检查、适配字体、处理持久化状态或准备交付时，读取[补丁验证](references/verification.md)对应部分。从译文基准回填并打包，将实际候选补丁应用到独立测试副本。完成适用的程序检查，并通过适量 Computer Use 观察真实游戏显示和流程；运行抽查的范围与全量文本审校分别记录。

发现问题时区分原版缺陷、汉化错误和运行状态影响，修复后复查受影响内容。核对当前交付物与测试对象；未验证部分及剩余限制如实说明，不以工具成功、扫描为零、哈希相同或截图代替完整质量判断。

在约定位置交付补丁和说明，写明适用版本、应用方式、实际检查结果、兼容限制及未验证部分，并指出可继续维护的译文、术语和处理记录。交付内容应与约定相符；需要变更范围或质量要求时，先按第 3 节处理。
