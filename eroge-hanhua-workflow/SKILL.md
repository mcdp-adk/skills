# 日文 R18 游戏汉化工作流

从用户提供的游戏和目标出发，按四个阶段完成汉化，交付适用于指定版本的补丁及必要说明、许可等相关内容。默认按公开发布的质量要求处理普通剧情、成人内容、界面、动态文字及中文载入和显示所需的适配；图片重绘和配音默认不纳入。用户明确的范围与质量要求优先，交付不等于获准公开发布或安装到用户游玩环境。

采用 KISS · YAGNI · SoC · DRY/SSOT · Fail Fast · POLA：利用已有机制和简单文件，分开维护译文与引擎加工逻辑；只增加实际需要的工具，生成产物来自明确的维护来源。发现错误就暂停依赖它的操作，独立工作继续。目录和数据用途保持清楚，不以整理全部资源或建设通用框架为前置目标。

先读已有约束、当前进度及相关复盘。新项目按四阶段推进；恢复、局部修订或单独审校从缺失结果接续，按改动回查受影响环节。已有约定和有效验证结果直接沿用。用户询问用途、从哪里开始或为何需要某步时，读取[工作流导航与答疑](references/guide.md)，先回答问题；仅咨询不启动制作。

## 第一阶段：确定产物边界与初步检查

先查用户已提供的路径和已有目录约定，给出工作目录、交付目录的推荐位置和简短用途说明，请用户确认或替换；两项已有明确选择时直接沿用。常规设置只询问这两个目录，内部采用[工作材料与流程衔接](references/materials.md#目录职责)的默认结构。按需建目录，已有项目按职责对应，不为统一名称搬迁材料。原版只读保留；用户游玩副本、存档和其他受限位置遵循具体授权。确认目录不扩大访问范围，也不授权覆盖其中已有文件。

确认后自主检查原版版本、引擎、主要语言来源、显示方式及已有工具，判断提取、回填和应用补丁的可行路径，列明实际资源缺口。原版位置不明等事实缺失才针对性询问。这里完成可行性初查，完整中文链路由第二阶段证明。需要运行原版时先读[测试环境与用户数据保护](references/verification.md#测试环境与用户数据保护)。

**完成条件**：两个目录及内部材料边界明确；原版与目标版本可定位，形成有依据的初步方案、代表样本选择和资源缺口。说明预期覆盖、保留的图片文字等内容及已知限制，必要信息写入当前进度入口。

## 第二阶段：跑通工作流

根据初查确认字体等必要材料是否可用。确有缺项或需要用户选择时，先说明发现、推荐方案、用途及获取或提供要求，一次处理一个需要决定的问题；已有材料足够就继续。样式偏好沿用既有约定，处理工具和常规实现由 agent 选择。资源不齐时推进不依赖它的工作，受阻路径标为待验证。

读取[工作材料与流程衔接](references/materials.md#从资源到翻译材料)，用代表内容串起提取或读取来源、准备翻译材料、翻译与审校、回填、必要适配、构建及应用。引擎机制决定拆包、解密、编译等具体操作；翻译执行者通过原文、译文和上下文工作，生成资源从维护材料取得译文。样本也按[翻译与审校](references/translation.md)的相关要求处理。

在测试副本中运行真实游戏，检查中文显示和相关操作；按[样本方法的适用范围](references/verification.md#样本方法的适用范围)验证可重建性及同类变化。只跑通完整链路，不以全量翻译或全部资源整理为完成条件；可一次提取的内容按效率处理，其余随批次扩展。失败先修复该路径，再扩大制作。

**完成条件**：代表内容可查原文与必要上下文、可维护对应译文，能重新生成并应用到测试副本，真实显示和操作正确。保留输入、步骤及适用范围，足以支持后续分批制作；未覆盖来源和全量字符集等事项进入第三阶段。

## 第三阶段：全量翻译与验证

沿已验证方法盘点全部纳入内容，包括脚本、界面、资源元数据和动态表达式中的语言内容，维护来源与处理状态。新发现的独立处理路径补做对应样本验证。原文、译文及回填关系按[材料衔接](references/materials.md#从译文到游戏资源)维护。

按剧情或功能关联分批翻译，保留原意、人物关系、视点、语气、语域、信息强度和不确定程度。短标签与动态片段放回完整用途判断。大量文本按上下文容量分配，主 agent 自行选择直接处理或委派，负责进度、疑义决策和合并统一；安排与恢复批次时读取[批次与上下文](references/translation.md#批次与上下文)，判义时按需查[术语辨义](references/terminology.md)。

全部纳入内容逐单元对照原文与上下文审校，再按剧情或功能连读中文；两项随批次完成，不推迟到最终验收。修正写回译文基准，术语变化回查相关内容。抽查和子 agent 完成声明不替代全量审校。查证后仍影响设定、全篇风格或大量译文的重要取舍，带依据和候选交用户决定。

每批按实际改动检查回填、格式、引用及相关显示，方法见[选择检查](references/verification.md#选择检查)。来源对应错误、控制信息损坏或必要引用缺失时，暂停依赖它的回填、构建或运行，修复后继续；不把工程问题积累到全量翻译结束。

**完成条件**：全部纳入内容已翻译、审校并正确回填，必要适配已完成，形成完整候选补丁。覆盖状态和验证结果可追溯，无未处理的已知错误；无法满足约定时，说明缺口并请用户决定受影响范围，不自行降低标准。

## 第四阶段：全面验收与润色

从干净的指定版本测试副本出发，按拟交付说明应用实际候选补丁。按[成品验收](references/verification.md#成品验收)核对全量内容状态，覆盖各类实际显示方式和受改动影响的操作、流程及适用的存读档行为。使用 Computer Use 或其他可用手段观察真实游戏，程序检查与真实运行分别取得证据；交付补丁不免除游戏验证。

结合实际场景检查语境、排版、人物口吻和跨批次一致性，针对发现的问题润色，回对原文。修改写回维护来源，重新生成受影响产物并复验；结尾按[确认交付对象](references/verification.md#确认交付对象)保证证据适用于最终包。语言全量审校已在第三阶段完成，此处补足成品中的呈现和整体体验，不无条件重做全部翻译审校。

**完成条件**：约定内容与受影响功能的验收已完成，已发现的问题已修复并复验；尚不能满足的要求经用户明确取舍。交付补丁、应用说明及必要相关文件，列明版本、实际验证范围、兼容限制和剩余问题，保留可继续维护的材料。主动解决可发现的问题，结论以实际证据为限，不承诺穷尽所有玩法或绝无缺陷。

## 持续维护

材料位置和唯一维护来源见[维护与交接](references/materials.md#维护与交接)。当前进度保留阶段、已完成内容、待办、阻塞及证据入口；沿用已有记录方式，简单项目用文件即可。每批读取相关术语，调查、修复和验证后只记录有新信息的复盘。工具故障与已有证据分开判断，按[复用证据与工具故障](references/verification.md#复用证据与工具故障)继续有效工作。
