# 日文 R18 游戏汉化工作流

## 目标与范围

交付经过验收、适用于指定原版版本的汉化补丁及必要附件。默认处理剧情、界面中的文本及动态生成的文字，完成翻译审校及中文载入、显示所需的适配；具体范围以用户约定为准。图片翻译、重绘和配音需另行确定。交付不包含公开发布或安装到用户游玩环境的授权。

遵循 KISS · YAGNI · SoC · DRY/SSOT · Fail Fast · POLA：复用适用机制，采用够用的文件结构，编辑成果与加工逻辑分别维护，发现错误时暂停依赖它的操作。原版只读保留，制作与测试围绕工作目录进行，交付目录只放最终补丁和必要附件；访问限制始终优先。

## 确认任务与工作目录

用户询问如何使用时，按 [使用与答疑](references/usage-guide.md) 解释。开始或继续制作时，读取用户指令、项目约定和已有入口，确认本次范围、完成标准、原版位置及访问边界。新项目按 [默认安排](references/workspace-and-collaboration.md#默认安排) 请用户确认工作目录、交付目录及工作和交付形式；已明确的选择直接沿用。

依据当前材料和进度安排工作，局部任务只处理约定内容及受影响部分。缺少信息时先查已有材料，再询问只有用户能提供的事实或决定；内部目录和常规制作选择由 Agent 处理。

## 调查与整理资源

按 [来源调查](references/production-workflow.md#调查来源与处理方法) 查明约定内容的分布及相关依赖，记录已确认来源、材料缺口和未知范围。调查不能止于已经提取的内容；未提取或读取失败的部分仍需跟进。

可以先用少量内容试验方法。扩大制作前，按 [材料组织](references/workspace-and-collaboration.md) 建立可查的来源记录和明确的编辑位置，使原始资源、编辑成果及生成结果能够对应，并按 [制作验证](references/production-workflow.md#验证制作方法) 证明这套方法可继续使用。无需先提取全部资源；后续发现的新来源和处理决定写回同一套材料。

## 翻译与适配

从已整理的材料开展工作，按 [汉化制作](references/production-workflow.md) 处理提取、载入、字体及必要显示适配。先核对现有资源，确需用户补充材料或选择方案时，说明实际用途、推荐方案和影响。

按 [翻译与审校](references/translation-and-review.md) 查阅并维护作品术语，完成约定内容的翻译、逐单元双语审校和中文连读。其他已获授权的资源制作沿用共同的材料边界，采用适合该资源的编辑和检查方法。

按 [成果采用与补丁生成](references/production-workflow.md#成果采用与补丁生成) 选择符合要求的成果。淘汰一份候选不等于取消对应任务；缩减约定范围或接受质量、验证缺口时，须带具体影响交用户决定。

## 验证与交付

制作过程中按 [检查对象](references/patch-verification.md#按工作选择检查) 验证方法、内容和受影响路径。启动游戏前先确认 [运行与数据保护](references/patch-verification.md#运行与数据保护)。语言审校与游戏运行验证各有完成依据，不能互相替代。

交付前按 [成品验收](references/patch-verification.md#成品验收) 核对范围，并在指定版本的干净测试副本上验证实际候选补丁。发现问题回到维护源修正，更新候选并复验受影响部分；仍适用的证据可以复用。完成后交付与证据对应的补丁及 [必要说明](assets/templates/patch-instructions.md)，如实说明覆盖和剩余限制，不以玩家后续反馈代替交付前验收。

## 协作与进度记录

不同 Agent 可以分别承担调查、翻译、适配或验证。按 [分工与接续](references/workspace-and-collaboration.md#分工与接续) 明确任务、完成标准、材料入口和写入责任，让接手者通过文件继续工作，无需依赖历史对话。

成果和处理状态写回各自维护位置；项目入口只汇总完成范围、证据入口、待办和下一步。条件满足后继续获授权的工作，遇到阻塞时推进不依赖它的任务。
