# 工作区与协作

确定目录、准备维护材料或接手他人工作时读取。制作方法见 [汉化制作](production.md)，语言判断见 [翻译与审校](translation.md)，测试要求见 [汉化验证](verification.md)。

## 默认安排

首次开始时，结合已有路径给出工作目录和交付目录的推荐位置，并说明制作材料留在工作目录、最终交付补丁及必要附件；请用户确认或替换。常规设置只涉及这两个目录及工作、交付形式。已有明确选择直接沿用，其余内部安排由 Agent 完成。

| 默认位置 | 维护内容与边界 |
| --- | --- |
| 工作目录 `README.md` | 项目入口，使用 [项目模板](../assets/templates/project.md) 记录实际约定、材料入口和当前任务；详细成果留在对应文件 |
| `GLOSSARY.md` | 项目术语的唯一维护入口，新项目采用含初始词条的 [术语表模板](../assets/templates/glossary.md)；已有材料的沿用与补充按 [作品术语](translation.md#作品术语) 处理 |
| `source/` | 从指定原版读取或提取的材料及来源定位，作为原文依据；不要求把整个原版复制进来 |
| `translation/` | 可修改的译文及翻译、审校状态；可直接采用引擎原生本地化文件 |
| `assets/` | 字体等制作所需材料，随材料保留来源与必要许可；原版提取资源归 `source/` |
| `tools/` | 实际使用的工具、配置和操作说明；可在 `README.md` 记录真实输入、操作、输出及适用条件 |
| `build/` | 从维护材料生成的加工结果与候选补丁，能够按记录的步骤重建 |
| `test/` | 独立游戏副本、测试数据与证据；验证结论默认汇入 `REPORT.md`，运行数据位置按 [数据保护](verification.md#运行与数据保护) 确定 |
| 交付目录 | 最终补丁和依据 [交付模板](../assets/templates/delivery.md) 编写的 `README.md`，以及必要许可、附件 |

以上是无既有约定时可以直接采用的结构，随阶段需要建文件和目录。已有项目在入口登记职责对应，不为改名而搬迁。开始写入前检查既有内容；原版和受保护位置不因被选作工作目录而获得写入许可。两个目录存在包含关系时，生成、清理与打包仍应明确各自目标，避免把制作或测试材料混入交付。

## 维护来源与生成结果

每种事实有明确的维护位置：译文在译文材料，术语决定在作品术语库，逐项检查结果在验证记录。项目入口提供位置和摘要，不复制另一套明细。

以文件承载的内容判断其职责。引擎原生翻译脚本、工具工程文件可以是维护源；自动生成过的文件若保存了唯一的译文、审校或编辑结果，也必须保留。将其登记为维护材料，后续生成读取它。只有修改已完整写回其他维护源且可重建的结果，才可作为生成产物处理。

提取材料保留原版版本及原始位置，发现提取错误时修提取方法或保存明确修正依据。修订译文后更新受影响产物，不能只修改最终包。维护源可按内容分成多个文件，保持各自责任清楚。

## 翻译材料的必要关系

已有适用的本地化格式时直接复用。没有合适格式时，从简单表格或文本记录开始，使每项内容能找到下列信息；具体序列化方式由实际载入方法决定。

| 信息 | 最低作用 |
| --- | --- |
| 来源定位与原文 | 能查回指定版本的文件、内部位置或稳定标识，并核对原文；原文相同但语境不同的内容仍可区分 |
| 当前译文 | 执行者能直接修改，回填或载入从这里取得译文；未译与有意保留原文可区分 |
| 处理状态 | 能找回未译、待审、已审和待查内容；中文连读涉及的范围也能追溯，沿用原生状态或简单标记即可 |
| 判义入口 | 能查到相关场景、相邻内容、说话人或使用条件；按需要提供引用，未知信息保留待查 |
| 格式约束 | 能识别必须保留的变量、标签及控制关系，执行者无需先理解整个构建实现 |

一段完整表达可能分布在多个来源项，一个共享项也可能有多个使用位置。按实际关系组织翻译，保存各自的实际对应；纯粹按原文字符串去重不足以确定译法。来源变动后先核对原文与定位，再复用旧译文。

## 分工与接续

项目入口的当前任务为不同 Agent 提供共同起点；用户也可直接指定一个更小的任务。接手者只读取本次所需材料，核对责任范围、完成标准、维护位置和已有结果；不依赖前一段聊天的摘要才能定位原文。

主导当前分工的执行者按剧情、功能或工程依赖划分工作。说明交付位置与可修改范围，让承担任务的 Agent 自主查证和处理。并行工作采用互不覆盖的写入范围；共享术语和跨范围修改由明确的负责人汇总，其他执行者提交有出处的候选或修正。更换负责人时，通过实际材料接续。

接续信息直接更新到项目入口：本次完成范围、成果链接、仍需处理的问题和下一步。逐项修正保存在译文，术语变更保存在术语库，检查证据保存在验证记录。合并时核对遗漏、重复、约定变化与任务交界；需要回查的已译或已审内容恢复为待处理状态。

执行者的完成声明用于定位成果，不能代替成果本身或必要检查。承担接续任务的 Agent 按本次范围核对相关结果，沿已有入口查证缺失信息。
