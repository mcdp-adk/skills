# 工作流导航与答疑

用户询问本 skill 的用途、从哪里开始、阶段差别或如何继续时使用。先结合其问题与已有进度给出简短直接的解释，再指出当前需要的结果和下一步；仅咨询不创建目录、不启动游戏、不开始翻译。执行规则以[正文](../SKILL.md)及对应参考为准，这份导航不另设验收条件。

## 按当前处境指路

| 用户处境 | 如何回答与指路 |
| --- | --- |
| 只有原版，想开始汉化 | 从正文第一阶段开始；解释工作目录保存制作材料，交付目录保存最终补丁。其余内部安排由 agent 按[目录职责](materials.md#目录职责)处理 |
| 不理解为什么需要字体或其他文件 | 结合已经调查出的具体用途解释，并给推荐选择；材料需求由正文第二阶段处理，不预先要求人人准备同一套文件 |
| 担心每个游戏都要重新设计流程 | 四阶段与材料衔接通用；引擎差异体现在提取、回填和显示实现，见[材料衔接](materials.md) |
| 已有提取文本或部分译文 | 查现有来源对应与已验证结果，补缺失环节后继续；无需无条件从头重做 |
| 想交给翻译 agent 或更换会话 | 指向[批次与上下文](translation.md#批次与上下文)，解释如何找到原文、译文、术语和待办 |
| 不明白第三阶段审校与第四阶段润色的区别 | 前者负责全部纳入文本的准确、通顺与一致；后者结合实际成品检查呈现和体验，修正发现的问题。细节分别见[双语审校](translation.md#双语审校)与[成品验收](verification.md#成品验收) |
| 游戏已经能启动，为什么还没交付 | 按[确认交付对象](verification.md#确认交付对象)指出具体未满足项；启动成功不能证明全部译文、操作或最终包正确，也不因无关工具故障否定有效证据 |
| 担心测试影响自己的进度 | 解释[测试环境与用户数据保护](verification.md#测试环境与用户数据保护)中针对当前游戏采取的措施；需要接触受保护数据时遵循明确授权 |
| 只想修一处译文或补丁问题 | 从该处来源和维护材料开始，修正后检查受影响范围；阶段是接续工作的依据，不是每次都完整重复的手续 |
| 想处理图片文字 | 区分提取图片辅助理解与翻译重绘图片。后者需明确新增范围与方法，不能因为图片已被提取就当作已承诺制作 |

## 回答边界

解释“为什么”时联系当前目标，例如来源定位用于查语境和正确回填，单一译文来源用于让修正进入最终包。用户问操作时给出当前可执行的下一步，不整篇复述工作流，也不把内部目录与工具选择变成额外问卷。

回答进度和完成情况前读已有记录，区分已经验证、尚未执行和确实受阻。信息不足时明确缺少什么；只有用户能提供的信息才询问。无法满足约定的范围、质量或访问要求时，说明具体影响和可行取舍，不把规则解释成自动扩大权限。
