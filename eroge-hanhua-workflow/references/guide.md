# 使用与答疑

用户想了解本 skill、参与方式或当前下一步时读取。先回答眼前的问题，再指出实际下一步。纯咨询不创建工作材料或启动游戏；用户要求开始、继续或修正时，再进入相应工作。

## 首次使用

用用户能理解的方式说明：用户提供游戏与目标，Agent 调查制作方法、安排翻译审校并验证实际游戏；用户通常只需确定工作目录、交付目录，并处理调查后确实需要选择或补充的事项。最后交付的是适用于指定版本的补丁及必要说明，制作材料保留以便继续维护。

用户要求开始后，按 [默认安排](workspace.md#默认安排) 进入项目准备。

## 按问题解释

| 用户的问题 | 回答依据与行动 |
| --- | --- |
| 为什么要提供字体？一个还是两个？ | 先给出已查明的显示用途与缺口，再按 [材料选择](production.md#必要材料与用户选择) 说明推荐方案和取舍。没有调查结果时先调查，不把两种画面风格直接等同于两份字体 |
| 有没有完成全部翻译？ | 从译文状态确认覆盖，分别说明翻译、双语审校和中文连读的实际完成情况；方法见 [审校与修正](translation.md#审校与修正) |
| 已经能启动，为什么还需要验证？ | 根据 [成品验收](verification.md#成品验收) 指出当前具体缺口，解释样本、完整内容与实际成品提供的证据不同 |
| 能不能交给另一个 Agent？ | 指向现有项目入口和实际成果，按 [分工与接续](workspace.md#分工与接续) 明确下一项任务；不用用户复制完整聊天记录 |
| 已经有一部分译文，或只想改一处？ | 识别实际维护源、来源关系和已有验证，补缺口并回查改动影响；不无条件重走所有阶段 |
| 测试会不会影响游玩进度？ | 说明针对该游戏实际采取的 [数据保护](verification.md#运行与数据保护) 措施。保护方案尚不成立时如实说明，明确受限位置始终排除 |
| 能不能一起翻译图片？ | 解释图片可以辅助理解文字；翻译重绘图片需要另定范围。若用户选择外部工具，届时再处理素材与作品术语的衔接，不自动承诺已经纳入 |
| 为什么这个译法还没确定？ | 给出原文依据、实际歧义和候选差别。普通查证由 Agent 继续完成；重要设定或整体风格取舍才交用户决定 |

## 解释结果与限制

报告前先查实际材料。让用户知道已经完成什么、证据支持到哪里、下一步是否需要其参与；尚未执行的检查和已失败的检查分别说明。无法满足要求时，说明具体影响及可行选择，不用内部术语或一长串技术选项代替推荐方案。

规则说明指回正文和对应参考；项目事实指回项目材料。用户不必学习整套目录或亲自编辑文件，也能委托制作和理解交付。
