# 翻译与审校

承担翻译、语言审校或润色任务时读取。维护位置与写入分工见 [工作区与协作](workspace.md)。语言任务以准确、自然且符合当前场景的完整表达为目标，执行者自行选择必要的查证和工作顺序。

## 开始一项语言任务

从项目入口和本次指令确认范围、目标、完成标准及成果位置，再读取相关原文、当前译文和作品术语。交给其他 Agent 时提供这些入口和可修改范围，让接手者按实际问题查阅上下文。

按足以理解含义的单元工作。一行、一个资源字符串或一次工具返回未必是完整表达；相关内容可以跨文件、跨任务，分支剧情也未必按文件顺序发生。需要承接前文时查相关原文与当前采用译文，必要时扩展到后文、条件或画面。已有译文帮助保持连续性，但不能覆盖原文或更新后的约定。

根据剧情、功能和上下文容量安排工作量，为疑义查证和审校留出空间。独立内容可以分工，存在依赖时先取得必要结果；并行写入和合并按 [分工与接续](workspace.md#分工与接续) 处理。执行者无需读取整个作品才能开始，但对当前表达的判断必须有足够依据。

## 理解原文与解决疑义

先确认谁在说、对谁说、描述什么，以及条件、时间、否定和确定程度。eroge 中同一角色的称呼、态度和语域可能随关系、场合或剧情阶段变化；普通剧情与成人场景都按实际表达判断，不能从类型标签推断人物关系或具体行为。

| 遇到的问题 | 优先补查的依据 |
| --- | --- |
| 省略、指代或动作方向不清 | 相邻应答、说话人、动作对象和触发条件；授受表达还原施事、受益方与视点，使役和受身区分谁使谁行动、谁受影响 |
| 同一词可能是姓名、称谓、机制名或普通描述 | 出现位置、作品术语及实际功能，确认当前类别和指代 |
| 文字不足以判断情境、情绪或界面用途 | 对应场景、立绘动作、截图或实际操作；先确认版本与场景对应，不凭画面补造设定 |
| 译法自然但会改变强度或信息 | 回看原文的委婉、粗俗、夸张、推测或传闻程度，保留原有语域和不确定性 |
| 双关、口癖或特殊用法 | 连看笑点、人物意图、重复位置和后文回收，再查必要辞书或语料 |

只补足理解和中文表达所必需的信息。已知某个委婉说法指向什么，并不意味着要把台词改成精确名称；人物的误解和叙事中的暂时隐瞒也要保留。成人语境中同样区分动作、参与者、结果与心理状态，不擅自改变同意、强迫或情绪关系。

授受表达的视点可能落在说话人以外的人身上；使役可以表达强迫、允许等不同关系。结合上下文确定人称与态度，敬称、自称和类型标签也只提供部分线索。拟声与声音表达区分动作声、身体反应和情绪，按整段节奏处理，保留原有表达强度。

疑义先由执行者沿原文查证。仍影响设定、整体风格或大量译文的取舍，带原文、候选及差别交用户决定；局部未决内容保留待查，其他独立内容可以继续。

## 作品术语

新项目以含通用词条的 [术语表模板](../assets/templates/glossary.md) 建立项目术语表，并登记维护位置。已有术语表或原生词典时直接沿用，按本次内容需要补入缺少的参考知识，保留已有作品决定。项目内只维护这一入口；日常翻译的修订写入项目材料，更新 skill 自带模板另属技能维护任务。

翻译与审校时查相关词条及适用条件，题材用语即使看似熟悉也核对含义和语域。先核对本作已采用的决定；没有项目决定时，以参考含义和译法为起点，结合原文选择。通用参考不是无条件替换表，未填本作决定也不表示该词未译。需要统一、存在特殊义项或译法调整时记录项目决定，其余直接据当前语境翻译。

遇到新词或现有条目不足时，先查作品出处和具体用法，再补查辞书、专业资料或适用语料；将有用的含义、参考译法及出处补入同一术语表。作品中反复出现的机制名、普通词的特殊义同样可登记。无法判明且影响译文的内容保留待查，避免把未查证猜测变成采用译法，其他独立内容继续。

人物名、别名、专名和需统一的称谓随发现登记，说明类别、指代对象和作品出处。类别按判义需要选择；身份未知时写明待查，职业标签和匿名称呼也可以成为条目，保留当时的信息披露程度。

同一对象的正式名、昵称和称呼可以关联，但各自保留适用条件。例如朋友使用昵称、下属使用职称、早期剧情隐藏身份，都不能全局替换成同一名字。同一个表面称呼指向不同对象时也应区分；只有关系有依据时才关联别名。

候选经作品证据确认后成为采用译法，记录适用条件与依据，普通确认由 Agent 完成。出现冲突时查原文并核对已有决定的依据；修订后定位受影响的译文、撤回失效的已审状态，完成修正复核并更新生成结果。共享材料按 [分工与接续](workspace.md#分工与接续) 的写入责任合并；工具发现也经同样核实后采用。

外部工具需要专用词典时，从作品术语材料提供适用内容并标明来源；工具新增发现回到同一维护入口判断，避免产生另一份独立权威词库。是否导出及用什么格式，由实际工具需要决定。

## 按表达任务处理

| 内容 | 主要判断 |
| --- | --- |
| 剧情对白与叙述 | 保留视点、人物口吻和信息披露；亲疏、敬意与情绪通过整句表达，不机械逐字保留语序或后缀 |
| 成人用语与声音表达 | 根据当前动作、感受、语域和节奏选词；避免把日常义一律成人化，或把委婉、粗俗表达统一成同一种强度 |
| 选项、按钮、活动和状态标签 | 结合用途与同组内容保留动作、对象和差别；选项不能擅自增强承诺、揭示结果或加入评价 |
| 称号、组合名称与动态句子 | 查完整组合及分支，判断片段的语法功能；独立标签与句内词形可能需要不同处理 |
| 玩家输入、插值与数值表达 | 保留变量身份及程序约定，按中文需要在允许范围内调整顺序；检查姓名、称谓、数值条件的完整表达 |

动态内容按各类实际组合判断，不靠逐片段翻译后盲目拼接。需要上下文变体或加载适配时，与制作任务协调；适配仍从明确译文维护源取得内容。不能删掉原意来满足长度或字节限制，显示限制先通过准确的简洁表达、布局或必要工程适配解决。

控制标记、转义和占位符按目标格式处理。不同引擎允许的重排与拆分不同，保留功能关系比机械保持文本位置更重要，技术检查见 [结构与载入](verification.md#结构与载入)。

## 审校与修正

第三阶段对全部纳入内容完成两类阅读，随实际工作推进；第二阶段代表内容同样适用。可以由独立 Agent 审校，也可以在当前任务中据原文重新判断，责任在于完成覆盖和有效复核。

| 阅读方式 | 判断重点 |
| --- | --- |
| 双语对照 | 逐单元核对原文、译文及语境，查漏译、增译、对象错配、条件否定变化、语域偏移、术语适用错误及控制信息损坏 |
| 中文连读 | 按连贯剧情或功能阅读中文，查前后照应、人物声音、搭配、节奏和选项差别；必要时跨越任务边界 |

审校者先理解原文，再评估现有译文和修改理由；修改应解决可说明的问题，不以个人同义词偏好反复推翻已经合适的表达。润色后回对原文，确认流畅度改善没有改变含义。

修正写入完整译文，状态记录实际完成范围。词义、关系或共用表达有变时回查相关已译内容，完成针对性复核后恢复已审状态。返回成果位置、疑义和需要协调的修改，摘要、抽查或完成声明不能代替全文审校。

第四阶段结合真实场景检查呈现与整体表达，补查和修正发现的问题；不无条件重做第三阶段全部阅读，也不以几个画面通过代替尚未完成的语言审校。

## 查证入口

补充语境材料时可查 [IGDA 的语境实践](https://igda.org/news-archive/high-quality-localization-help-loc-help-you/)；安排游戏内语言检查时可查 [IGDA 的 LQA 实践](https://igda.org/news-archive/how-to-get-the-most-from-lqa-what-it-is-and-best-practices/)，区分文本审校与实际呈现中的问题。

授受视点可查 [国際交流基金的语法说明](https://www.jpf.go.jp/j/project/japanese/teach/tsushin/grammar/201409.html)；使役的意义区别可查 [早津恵美子的研究](https://www.jstage.jst.go.jp/article/gengo/148/0/148_143/_article/-char/ja/)，使役受身可查 [国際交流基金教材](https://www.kyozai.jpf.go.jp/kyozai/material/BMA00076/ja/render.do)。
