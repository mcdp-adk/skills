# 汉化验证

证明制作方法、中文呈现或最终补丁是否满足要求时读取。先确定实际对象和要证明的结果，再选择检查。语言质量按 [翻译与审校](translation.md#审校与修正) 完成，验收时读取对应状态与结果。

## 按阶段选择检查

| 当前工作 | 必须回答的问题 |
| --- | --- |
| 初查 | 原版、来源和显示机制是否可定位，初步方法有什么依据，哪些仍需通过实际链路验证？ |
| 代表链路 | 译文是否从维护源实际生效？修改维护源后能否重建并应用到干净测试副本？所选同类变化是否仍保持含义、结构和操作正确？ |
| 扩大制作或局部修正 | 本次内容是否遗漏、错位或损坏？新的来源、字体、动态表达或逻辑改动需要补验哪些路径？ |
| 完整候选 | 全部纳入内容、显示方式和受影响行为是否有适用证据？用户按说明应用的实际补丁是否取得同样结果？ |

代表内容按已经识别的路径及其限制选择，例如不同长度、字符、控制信息或动态条件。一次固定样本成功不能证明方法适合全量；尚未纳入样本的独立路径在遇到时补验。临时演示与正式制作的区别见 [代表链路与重建](production.md#代表链路与重建)。

检查应读取实际被测内容。格式检查、编译、模拟求值、自动操作和人工观察各有适用范围；工具成功退出、菜单启动或没有缺字日志，都只能说明实际检查过的部分。自写检查若承担关键判定，用有效样本及针对性反例确认它确实能发现所声称的问题。

## 结构与载入

- 将纳入来源与译文、实际载入结果对应，查遗漏、重复、错位和未判定项。日文残留扫描只是线索，纯汉字标签、动态文字和有意保留的内容要分别判断。
- 按目标格式检查编码、控制结构、变量身份、转义、标签和资源引用。允许的顺序调整、拆分与实际损坏应区分，不能对不同引擎强制同一种条目或占位符数量规则。
- 核对真实加载入口、资源优先级、语言选择和必要依赖；译文在文件里存在不等于游戏正在使用它。
- 动态表达既核对模板及组合条件，也检查代表输入的完整结果。独立脚本求值不能自动证明游戏中的相同显示或行为。
- 对照指定原版判断资源缺失、异常和告警的来源；没有相同条件的对照时保留待查，不把疑似原版问题写成已确认结论。

## 中文显示

沿各类实际显示路径核对字形来源与版面：正文、界面、输入位置、特殊样式或字形图集是否使用预期资源。固定译文检查完整字符集合；支持玩家输入时按约定范围检查，不能用仅包含固定台词的子集字体证明任意输入可用。

区分字形是否存在、游戏是否加载、实际呈现是否合适。根据格式检查真实字符映射或等价引擎结果，再观察简体字形、标点、回退、换行、裁切、遮挡和可读性。字体名称或文件中出现某个码点字节不构成充分证据；系统回退也可能隐藏补丁缺少依赖的问题。

结合长短文本、相关符号和实际允许的输入边界取样，发现布局问题时追查字体度量、控件或规则。样本阶段未译文字的过渡性缺字应标清范围，最终纳入内容的缺字仍需解决。材料选择由 [制作参考](production.md#必要材料与用户选择) 负责，不能为通过显示检查而牺牲原意。

## 运行与数据保护

任何实际运行前，确认游戏副本及会影响用户进度、设置或验证结果的运行数据。优先使用独立测试游戏和简单、受支持的数据隔离办法；存档、持久解锁、配置或同步数据可能位于游戏目录之外，复制游戏文件不保证它们独立。

按实际风险保护数据。普通日志、缓存位于外部不单独阻断运行；若涉及共享状态或明确受限位置，仍需处理。需要接触用户数据时遵循当次明确授权，在备份测试副本上操作，修改实际游玩存档另需明确授权。

明确禁止访问的路径始终排除。不能排除覆盖真实进度或重要设置的风险时暂停该次运行，说明具体缺口并继续独立工作。已成立的保护措施可以复用，环境或启动方式变化时再核对是否仍适用。

## 场景、操作与存档

按实际作品的显示与玩法选择场景。对白、分支选项、关系阶段、回想、状态或其他系统中的文字可能经过不同路径；覆盖适用路径，不把单一菜单视为整部游戏，也不要求所有作品都按同一玩法清单测试。

选择、输入或动态状态的改动要检查对应行为，字体与共用脚本改动要扩大到其影响范围。可以使用已有章节入口、回想或独立测试存档；必要时构造最小测试状态，先查清依赖，再由真实游戏载入。记录入口和状态来源。人为跳转后的画面正确不自动证明自然流程可达或存读档行为正确。

旧档可能保留文字、键、脚本位置或派生状态，独立系统数据也可能保存已读和解锁信息。改变显示标题与改变程序标签、返回位置的影响不同。新游戏正确而读档异常时，查值来自资源、初始化、存档还是缓存；若需要兼容修复，先核实字段和引用，保留进度及其他状态，再针对性修改并复验。首版采用新游戏验证不永久排除旧档支持；没有获授权的真实旧档时，只能报告已测测试数据的范围。

## 成品验收

从指定版本的干净测试副本出发，按拟交付说明应用实际候选补丁。核对以下适用方面；已完成且仍对应当前对象的证据可以复用，实际缺口需要补齐。

| 方面 | 完成依据 |
| --- | --- |
| 内容 | 纳入来源有去向，译文及全量双语审校、中文连读已完成；范围外保留内容有说明 |
| 呈现 | 完整译文及约定输入范围具备字形支持，各类显示路径有实际观察；语境、称呼和排版问题已修正 |
| 行为 | 受影响的操作、动态表达、分支及适用的存读档行为有对应检查，问题修复后已复验 |
| 补丁 | 实际交付内容来自维护源，按说明可应用；不依赖未交付的工作文件、临时设置或隐含资源 |
| 说明 | [交付说明](../assets/templates/delivery.md) 对应实际版本、操作、许可、兼容范围和已知限制，必要恢复方法有依据 |

全面验收指各适用方面有充分依据，不等于穷尽全部玩法。发现语言或工程问题时回到对应维护源修正，更新候选并检查受影响部分。无法满足约定的要求时，把具体缺口和可行取舍交用户决定，不自行降低标准。

## 证据与接续

每项记录能回答：测了哪个版本或候选对象、用什么方法和状态、实际发生了什么、支持何种结论、还有哪些未覆盖。按 [默认安排](workspace.md#默认安排) 保存结论与证据，现有报告能承担职责时直接沿用；项目入口引用即可。

候选包或条件变化后，判断哪些结论受到影响。文件清单或哈希可以帮助核对对象，不能替代语义或运行验证。只改变无关元数据不必全部重测；相关内容变化、相反证据或检查误判则需补验。

工具当前故障和已有证据分别判断。启动前失败不能写成运行通过，也不自动推翻同一候选先前有效的运行结果。修复或替换被阻塞的手段，继续不依赖它的任务；接手 Agent 据实际材料辨认仍有效的结果和待验证部分。

## 查证入口

[KAG 存档数据](https://krkrz.github.io/krkr2doc/kag3doc/contents/SaveData.html) 说明标签、调用位置和系统状态的关系；[WOLF 保存与读取](https://silversecond.com/WolfRPGEditor/Help/04ev_file.html) 展示不同状态保存方式；[Ren'Py 开发工具](https://www.renpy.org/doc/html/developer_tools.html#lint) 明确区分 lint 与实际测试。这些资料支持检查思路，具体引擎和版本的路径、控制方法仍需现场核实。
